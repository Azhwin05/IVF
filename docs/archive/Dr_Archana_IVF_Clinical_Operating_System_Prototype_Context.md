# Dr. Archana IVF Clinical Operating System

## Master Prototype Context Prompt

### Product Descriptor
**A secure, integrated IVF Hospital Management System designed around the complete fertility patient journey.**

---

## 1. Project Objective

Design and build a **premium, high-fidelity, interactive desktop web application prototype** for **Dr. Archana IVF & Women Centre**, a fertility and women’s healthcare hospital in Anna Nagar, Chennai.

This is not a public marketing website and not a consumer mobile application. It is a **Hospital Management Information System (HMIS)** and **IVF Clinical Management Platform**, accessed through a secure web application by authorized hospital staff.

The prototype must make the hospital owner, doctors, clinical staff, and management feel:

> “This system understands how our IVF hospital operates. It can bring our complete patient journey, clinical records, embryology workflow, billing, and hospital operations into one connected platform.”

The product should feel like a **premium IVF Clinical Operating System**, purpose-built for the hospital—not like a generic admin dashboard with medical forms added.

Demonstrate this journey:

**Patient Registration → Consultation → Fertility Assessment → Treatment Planning → Ovarian Stimulation → Follicle Monitoring → Trigger → Oocyte Retrieval → Embryology → Embryo Transfer → Pregnancy Follow-up → Treatment Outcome**

The experience must be visually impressive, clinically organized, calm, trustworthy, and operationally believable.

---

## 2. Product Positioning

> **Dr. Archana IVF Clinical Operating System**  
> One secure platform connecting the complete IVF patient journey with clinical care, embryology, billing, laboratory, pharmacy, inventory, and hospital management.

Do **not** position it as:

- A normal website
- A simple clinic appointment application
- A generic hospital dashboard
- A consumer mobile application
- A basic patient-record system
- A collection of unrelated forms

It is a comprehensive **IVF-focused HMIS**, delivered through a secure desktop-first web application.

## 4. Design Direction

The design must feel:

- Premium
- Calm
- Warm
- Trustworthy
- Private
- Clinically sophisticated
- Modern
- Minimal
- High-end
- Human-centered

Avoid:

- Crowded government-portal styling
- Generic SaaS dashboards
- Dark cyber-security dashboards
- Basic Bootstrap admin templates
- Colorful generic HMIS templates
- Data-heavy spreadsheet interfaces

Use:

- Generous white space
- Soft neutral backgrounds
- Warm brand colors inspired by the hospital identity
- Elegant typography
- Rounded cards with subtle borders
- Very soft shadows
- Clear information hierarchy
- Large, readable patient information
- Clean clinical tables
- Minimal visual noise
- Calm status indicators
- Consistent iconography

Do not use excessive gradients, neon colors, excessive glass effects, oversized shadows, or decorative illustrations inside the clinical workspace.

The system should combine the emotional warmth expected from fertility care with the precision expected from clinical software.

# 9. UX Principles

## Clinical Clarity

Important patient information should be visible immediately.

## Low Cognitive Load

Do not show unnecessary information.

## Fast Workflow

Common actions should require few clicks.

## Patient Safety

Critical actions should include:

- Confirmation
- Verification
- Clear status
- Responsible staff member
- Date and time

## Context Preservation

The doctor should not lose the current patient context when moving between consultation, monitoring, treatment, embryology, and procedures.

## Progressive Disclosure

Show the most important information first. Allow detailed information to expand when needed.

## Consistency

Use the same:

- Status badges
- Card patterns
- Table design
- Form controls
- Button hierarchy
- Typography
- Spacing

across the application.

# 10. Status System

Use consistent, controlled status colors:

- Completed — subtle green
- Active — brand primary color
- Pending — soft neutral or amber
- Attention Required — controlled amber
- Critical — muted red
- Scheduled — soft blue
- Cancelled — neutral gray

Do not use bright or highly saturated colors.

# 12. Content and Microcopy

Use professional, human language.

Use:

- “Patient profile created successfully.”
- “Clinical review saved to Priya’s treatment timeline.”
- “You do not have permission to view embryology records.”
- “Remove this draft clinical note?”

Avoid:

- “Data successfully inserted.”
- “Record updated.”
- “Error 403.”
- “Delete?”

# 13. Important Design Restrictions

Do not:

- Use lorem ipsum
- Use generic dummy patient names
- Create empty dashboards
- Use excessive gradients
- Use excessive glassmorphism
- Use neon colors
- Use a dark hacker-style interface
- Use generic Bootstrap admin styling
- Use dense spreadsheet-like layouts
- Use overly rounded cartoon-style components
- Add unnecessary animations
- Add fake AI diagnosis
- Automatically recommend clinical treatment
- Make medical decisions without doctor approval
- Expose sensitive embryology information to every role
- Make the system look like a public website
- Make the system look like a mobile social application
